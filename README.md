## 처음 실행하는 분께

`../WindowsBuild/Valhalla.exe`를 실행하세요. 실행 파일과 Valhalla_Data 등 동봉 파일은 함께 유지합니다. Unity에서 수정하려면 이 폴더를 Unity Hub에 추가하고 `Assets/Scenes/Lobby.unity`를 열어 Play를 누릅니다.

이 프로토타입의 중심은 **문신으로 싸움법을 구성하고, 부상의 위험을 감수하며 전리품을 회수하는 것**입니다. 로비에서 마을로 들어가 오른쪽 훈련장에서 E를 누르세요. 훈련 후 화면 안내를 따라 재료 확인 → 가공 → 판매 → 문신·장비 준비 → 오른쪽 관문 출정으로 이어집니다. 안내는 순서를 강제하지 않습니다.

- 이동 A/D, 점프 Space, 일반 공격 J, 강공격 K, 대시 Shift, 패링 C, 박치기 Q, 잡기/투척 V, 상호작용 E, 소지품 I, 메뉴 Esc.
- 강공격은 누르자마자 준비합니다. 대시는 이동 입력 방향이 우선이고, 입력이 없으면 바라보는 쪽입니다.
- 처음에는 오른팔의 천둥 문신으로 강공격을 시험하세요. 마을에서 오른다리의 질주 문신을 획득·장착하면 대시 충돌을 공격으로 활용할 수 있습니다. 잠긴 문신도 효과와 해금 조건을 읽을 수 있습니다.
- 외상 30에서 자동 적응, 55에서 그 부위의 모든 문신이 침묵합니다. HP 회복으로 외상은 없어지지 않습니다. 다음 출정 때 복구됩니다.
- 숲 → 광산 → 성소의 세 지역을 진행합니다. 방을 정리한 뒤 중도 귀환할 수도 있습니다. 귀환하면 재료 전부, 사망하면 종류별 절반을 보관합니다. **출정 도중 종료한 방 진행과 미보관 전리품은 저장되지 않습니다.**

현재 Windows 검사는 캠페인 297개·전투 회귀 21개 통과이며 빌드 전 규칙 12개도 통과했습니다. 자동 검사는 실제 씬·전투 업데이트와 동작 메서드를 사용합니다. 물리 키 입력 전체, 첫 사용자의 이해도와 주관적 손맛은 아직 검증 완료로 표시하지 않습니다.

아래는 버전별 작업 기록입니다. 실행·조작·경제·MDA/SOLID·패턴의 상세 설명은 뒤의 해당 절을 참조하세요. 버전 기록의 당시 미구현 항목은 최신 상태와 다를 수 있습니다.

## 0.16 — 패링 C / 잡기·투척 V

사용자가 F/G의 손가락 이동이 불편하다고 피드백하여 C 패링, V 잡기·투척으로 변경했습니다. 입력 경로·전투 HUD·적 예고·튜토리얼·문신 발동 안내·물체 운반 안내를 함께 갱신했습니다. 이전 F/G는 전투 입력으로 사용하지 않으며 0.15의 타이밍·피해·버퍼·UI 접기 규칙은 유지합니다. 이후 문서의 F/G는 당시 버전 기록이고 현재 조작은 C/V가 우선합니다. 키 참조 충돌과 오래된 실행 화면 문구를 소스 검색으로 확인하고 Windows 빌드를 갱신했습니다. 키 배치·표시만 바뀌므로 전투 메서드 검사 297/21을 반복하지 않았으며 실제 C/V 키 감각은 사용자 플레이로 확인합니다.

## 0.15 — 사용자 피드백: 패링·대시 반응과 전투 UI

마을 UI도 기본적으로 간결하게 표시합니다. 은화·무기·장착 문신 수와 첫 출정 단계/목적 시설/방향을 남기고, 전투용 신체·문신 상세와 긴 안내는 Tab으로 펼칩니다. 최근 귀환 결과는 오른쪽의 Tab 안내로 접근하고 시설 근처 E 안내는 화면 아래에 표시합니다. 상점·문신소 패널을 열면 기존 세부 거래/장착 정보를 유지합니다. 훈련 중 단계 설명은 유지합니다. Windows 빌드와 첫 방문/Tab 상세/문신소 화면을 메모리 프로필로 확인했습니다(compact-village-ui.png, expanded-village-ui.png, compact-village-tattoo-open.png). 표시 변경이므로 기존 297/21 검사 전체는 재실행하지 않았습니다.

사용자는 패링 타이밍·대시 반응과 UI가 거슬린다고 피드백했습니다. 방어 입력(F/Shift) 보관을 0.25초로 늘리고, 실제 타격이 끝난 공격의 마지막 0.12초 후딜에서 방어로 전환하도록 변경했습니다. 강공격의 즉시 준비·0.43초 타격은 유지하고, 타격 전 취소는 막습니다. J/K 공격 입력은 0.15초이며 후딜을 취소하지 않습니다. 방어 재사용 시간이 남으면 후딜도 취소하지 않습니다. 이 변경은 아래 0.14의 '후딜 완전 보존/모든 입력 0.15초'보다 우선합니다.

적의 예고 진행 막대를 추가하고 '지금 F'는 실제 위협까지의 예상 시간을 사용합니다. 돌진 이동 시간·거리·높이·잡힘/경직과 현재 왼팔의 패링 시간을 반영합니다. 현재 위치를 기준으로 한 예상 안내이며 미래 이동을 예측하거나 성공을 보장하지 않습니다. 판정 시간 자체는 정상 0.45초, 적응 0.36초, 심각 0.25초를 유지합니다.

일반 던전 전투에서는 큰 좌우 문신/신체/박치기/잡기 패널과 긴 상시 조작 설명을 접습니다. 상단 생명·명예, 하단 K/F/Shift 상태, 짧은 발동/적응/침묵 알림만 유지합니다. Tab으로 상세 화면을 펼치거나 접으며 전투는 계속됩니다. 훈련·마을·열린 메뉴는 기존 안내를 유지합니다. 가까운 적과 싸울 때 상자 근접 설명은 숨깁니다. 제어된 compact-combat-ui.png / expanded-combat-ui.png / compact-injury-ui.png로 확인했습니다.

MDA: 방어 입력 여유·타격 후 제한적인 전환 → 늦은 반응도 방어로 연결 → 묵직함을 유지하면서 입력 누락감 감소. 화면 정보 우선순위 → 적과 동작에 집중 → 전투 판독성. 입력 정책은 Barbarian, 읽기 전용 위협 예상은 Enemy, 정보 배치는 CampaignHUD가 맡습니다. Claude의 첫 프로토타입 범위 감사는 기존 기능의 근거와 사용자 체감 확인 필요성을 구분했고, 이어 도착한 사용자 피드백에 대한 이번 수정은 Codex가 수행했습니다(../Claude-첫프로토타입-출시범위점검.txt).

Windows 캠페인 297개·실패 0개, 전투 회귀 21개 통과. 강공격 준비 취소 방지·실시간 후딜 전환·입력 만료·방향, 부상별 안내 시점·돌진 접근·잡힘 제외를 검사했습니다. 이후 상자 안내 숨김/문구 변경은 최종 빌드와 화면으로 확인했으며 전체 캠페인을 다시 반복하지 않았습니다. 새 체감에 대한 사용자 확인은 남아 있습니다.

## 0.14 — 전투 입력을 짧게 보관

문신 월드 피드백: 천둥은 번개 룬, 질주는 실제 수평 대시 방향의 이중 궤적, 반격은 전방 호로 구분합니다. 기존 입자·음향과 함께 발동 순간을 표시하며 피해나 범위를 나타내는 충돌 경계는 아닙니다. Claude Code가 TattooWorldFeedback을 작성하고 Codex가 방향 보정·수명 정리·Game/방 전환 연결과 검증을 맡았습니다. 보고서는 ../Claude-문신월드연출-작업보고.txt입니다.

MDA: 서로 다른 능력의 형태 → 발동한 능력과 이동 방향 판독 → 문신 구성의 체감. Observer(TattooSignals)로 전투와 표현을 분리하고 6개 LineRenderer 풀을 재사용합니다. 자체 난수를 쓰지 않고 HP·피해를 변경하지 않습니다. 심각 부위는 Has로 차단, 메뉴/타격 정지는 진행 시간을 멈추며 방 전환·종료 때 Clear합니다. 현재 3종에만 전용 형태를 추가했으며 나머지 12종의 전용 형태는 아직 없습니다.

Windows 캠페인 292개·실패 0개. 반대 방향/낙하 중 질주, 세 형태·난수/HP 보존, 메뉴 정지·재개 만료, 심각 부위 차단, 실제 LoadRoom 정리를 검사했습니다. Previews/tattoo-{thunder,ram,reprisal}-feedback.png는 이벤트를 직접 발행하고 타격 정지로 고정한 제어 화면이며 자연 플레이 캡처는 아닙니다.

Claude 독립 검토 후 전투 중 HUD 클릭이 일반 공격도 시작시키던 문제를 수정했습니다. 소지품·기록·훈련 나가기 버튼의 동일 Rect와 현재 화면 배율을 입력 단계에서 검사합니다. OnGUI의 이전 프레임 상태에 의존하지 않으며 열린 패널은 마우스 공격을 차단합니다. J/K 키보드 입력과 전장 마우스 공격은 유지합니다. Windows 캠페인 286개·실패 0개: 버튼/전장/훈련 종료 영역, 열린 패널, 실제 LoadRoom의 예약 입력 정리를 추가로 확인했습니다. 물리 마우스를 자동 클릭한 검사는 아닙니다.

검토 원문은 ../Claude-014-전투입력표시-검토보고.txt입니다. 보급함 문서 지적은 검토 도중 이미 수정된 문구를 대상으로 했으며 현재 README와 코드의 외형 설명은 일치합니다. 시체 운반에도 근접 안내를 추가하자는 지적은 후속 사용성 보완으로 남깁니다. 현재 상자 안내만으로 시체 안내까지 구현됐다고 주장하지 않습니다.

상자 용도 안내: 가까운 상자 하나에 재료 상자(J/K 파괴) 또는 운반 상자(G 들기/K 밀기/압력판)를 표시합니다. 들고 있거나 패널이 열렸을 때는 근접 안내를 숨깁니다. 모든 상자를 파괴한다고 오해할 수 있던 입장 안내도 구분했습니다. 캐릭터를 가리지 않도록 안내를 위에 배치한 실제 제어 화면(crate-affordance.png)을 확인했고 Windows 빌드에 반영했습니다. 표현/문구 변경이며 전투·퍼즐 판정은 유지합니다.

시각 보완: 단순 색상 블록이던 파괴/운반 상자를 생성한 목재·철제 상자(SupplyCrate-v1.png)로 교체했습니다. PaintedCrateVisual은 부모의 상호작용을 유지하고 자신이 만든 Sprite만 해제합니다. 이미지가 없으면 기존 도형으로 표시합니다. 원본 RGBA와 전체 프롬프트·알파 기준 Sprite 영역은 Design/crate-art-provenance.json에 보관했습니다. 보급로 화면에서 크기·바닥 정렬·배경 조화를 확인했고 Windows 캠페인 281개가 다시 통과했습니다. 봉인 보급함에도 더 큰 목재 외형과 작은 상태 봉인을 적용하고 압력판 활성·보상 지급을 제어된 에디터 실행으로 확인했습니다(supply-vault-art.png). 보급함 주변 운반 안내와 E 안내도 겹치지 않게 배치했습니다. 압력판은 기존 도형입니다. 최근 에셋/연결은 Codex가 작업했으며 0.14에 대한 Claude 독립 검토를 재개했습니다.

문신 목록은 이름 아래 실제 발동 키/조건과 일시 상태를 표시합니다. 응수·재의 반격·거인 반격은 강화의 남은 시간, 고통의 메아리는 다음 박치기에 저장한 피해, 발키리의 맹세는 명예 조건 또는 출정 중 소진, 최후의 숨·대지의 발은 재사용 시간을 보여줍니다. 심각한 부위는 이 상태 대신 침묵을 표시하고 마을에서는 발동 안내로 돌아갑니다. TattooCombatEffects.StateHint는 읽기 전용이며 충전 소비·피해·타이머를 변경하지 않습니다. 8개 문신·충전·소진·침묵을 설정한 제어 화면에서 목록 범위 안에 표시됨을 확인했습니다(Assets/Previews/tattoo-live-state.png). Windows 빌드 성공. 이번 표시 변경은 기능 회귀 전체를 다시 실행하지 않았습니다.

조작 상태 표시를 추가했습니다. 상단 K/F/Shift 줄은 준비·후딜·패링 판정·재사용 대기·운반 제한을 실제 상태에서 읽고, 하단은 보관 중인 입력을 표시합니다. 적이 가까이 모이면 체력/패링 안내를 세로로 분리해 겹침을 줄입니다. 전투 수치는 변경하지 않았습니다. Windows 빌드 성공, 두 적을 같은 위치에 둔 제어된 에디터 화면에서 후딜·예약 패링·분리된 예고를 확인했습니다(Assets/Previews/combat-readiness.png). 이전 281개 캠페인/21개 전투 검사 이후의 이 변경은 읽기 전용 HUD이며 전체 검사를 재실행하지 않았습니다.

## 0.5 구현 기록 — 일곱 부위에 새기는 문신

머리·가슴·등·오른팔·왼팔·오른다리·왼다리를 각각 장착·피격·부상 단위로 다룹니다. 오른팔 면적 2, 나머지 각 1이며 문신은 총 11종입니다. 기존 저장의 `Legs` 값과 다리 문신은 오른다리로 유지하고 왼다리를 추가했습니다. 반격의 각인은 기존 오른팔 배치를 유지하며 새 왼팔 능력은 응수의 낙인입니다. 소유품이나 의도적으로 비운 장착 상태를 덮어쓰지 않습니다.

일곱 부위의 심각한 부상·최후 피격 기억은 정산·저장합니다. 새 부위 기억의 추가 해금과 적/피해 유형별 흉터는 아직 남아 있습니다. 기존 오른팔/오른다리 해금 2종은 유지합니다.

- G: 약화되거나 경직된 작은 적 잡기. 잡은 동안 다시 G로 투척. 정면 공격 한 번은 인간 방패가 대신 맞습니다.
- J / 좌클릭: 일반 공격. K / 우클릭: 강공격. 누르는 순간 준비 동작을 시작하고 0.43초 후 타격합니다. 버튼 유지 충전이 아닙니다.
- Shift: 좌우 이동 입력 방향으로 대시. 입력이 없으면 바라보는 방향으로 이동합니다. 적을 지나쳐도 진행 중인 대시는 반대로 꺾이지 않습니다.
- F: 패링. 입력 후 0.45초 동안 유효하며 재사용은 0.60초입니다. 적의 공격 직전에는 ‘지금 F · 패링!’이 나타납니다.
- Q: 박치기. 생명 4를 즉시 쓰고 0.16초 준비 후 가장 가까운 전방 적 1명에게 피해 8과 행동 중단을 줍니다. 총 동작 0.42초, 재사용 1.3초. 일반 적 0.8초/정예 0.55초/보스 0.35초 경직. 빗나가도 비용을 쓰며 무적은 없고, 생명 4 이하에서는 사용할 수 없습니다. 피격 시 남은 판정은 취소됩니다.
- E: 시설 / 관문. I: 소지품. Esc: 메뉴 또는 열린 패널 닫기.
- F1: 개발 도구. 활성 중 F6/F7 오른팔/다리 강제 피격, F8 체력 회복.

외상 14 손상 경고(기능 유지) → 30 자동 분노 적응 (전투 지속) → 55 심각한 부상.
심각한 부상에서는 해당 부위의 모든 문신과 문신 의존 융합 효과가 꺼집니다.
오른팔: 후딜 ×1.9, 적응 적용 후 강공격 피해 ×0.7. 다리: 이동 ×0.48, 돌진 속도/재사용 제한.
반대 부위의 문신은 유지됩니다. 체력 회복은 외상을 제거하지 않습니다. 다음 출정에서 부상과 적응을 초기화하고 문신을 복구합니다.

둘 다 시작 예산 안의 선택지이며 우열을 확정한 추천 빌드는 아닙니다. 두 번째 구성에서 반격 구매가 ‘보관 획득’으로 표시되면 천둥을 해제한 뒤 반격을 장착하세요. 소유만 한 문신은 발동하지 않습니다. 첫 훈련은 개인 구성과 별개로 천둥·질주를 빌려 쓰고 종료할 때 개인 장착을 복구합니다.

`--combat-journey` 진단 옵션은 `--journey-seed 정수`, `--journey-elite`, `--journey-parry`를 지원합니다. 결과 파일명은 `combat-journey-{시드}-{supply 또는 elite}-{thunder 또는 parry}.txt`입니다. 문신 발동 이벤트도 기록합니다. 시드 1337 보급로의 패링 구성은 9방 승리·마을 귀환, 반격 11회·피의 룬 14회 발동, 최종 생명 32.4를 기록했습니다. 자동 정책·실시간 실행의 한 사례이며 플레이어 성능 비교 수치로 일반화하지 않습니다.

마을 화면에서 훈련 → 소지품 → 가공 → 판매 → 문신소 → 장비 상점 → 출정의 다음 행동과 시설 방향을 안내합니다. 성공한 거래와 실제 패널 방문을 기록해 저장하며 순서와 관계없이 자유롭게 진행할 수 있습니다. 자원이 부족하면 먼저 던전에 다녀와도 됩니다. 새 안내 필드는 기존 저장에서 미완료 상태로 시작하며 아이템과 재화는 유지합니다.

VillageGuide는 프로필을 읽어 다음 안내만 계산합니다. 진행 기록은 EconomyService의 성공한 거래와 CampaignDirector의 시설 방문·출정에서 갱신하므로 화면 표시와 거래 판정을 분리합니다.

## 마을·제작·경제

- 훈련장: 이동/점프, 강공격, 패링, 대시, 자동 부상, 심각한 부상 학습. 사망 방지, 다시 배우기, 첫 완료 재료 지급.
- 대장간: 원재료 2 → 가공품 1. 가죽·뼈·철 가공, 단조 도끼/가죽 보호대/회복 연고 제작.
- 부산물 상인: 수량·총액을 확인하고 판매, 취소 가능.
- 장비 상점: 도끼 / 보호대 구매와 장착. 방어구는 한 부위만 보호하며 외상 누적 ×0.75.
- 문신소: 15종 문신의 획득·장착·해제. 7부위를 선택하며 오른팔 면적 2, 나머지 각 1. 모든 효과는 BodyBuild.Has로 부상 활성 상태를 검사합니다.
- 소지품: 마을 보관품과 이번 출정 미보관 재료를 분리 표시. 던전에서 연고 1개 사용 시 생명 35 회복, 외상 유지.

안전 귀환은 전리품 전부, 사망은 종류별 절반(소수점 버림)을 보관합니다. 마을 보관품과 구매 장비/문신은 유지합니다.
보관 한도 초과분은 판매가로 정산합니다. 귀환/사망은 한 번만 정산됩니다. 명예는 패링·대시·처치로 늘고 장시간 도주하면 줄며 은화 보상에 반영됩니다.
출정 정산 시 심각하게 다친 부위 또는 최후의 피격 부위에 기억을 1회 기록합니다. 오른팔 기억 2회는 메아리, 다리 기억 2회는 서리 발걸음을 해금합니다. 문신소에서 무료로 획득한 뒤 면적에 맞춰 장착하며, 자동 능력치 보너스는 주지 않습니다. 반복 정산은 기억을 중복 지급하지 않습니다.

거래와 준비 상태는 Application.persistentDataPath/campaign-v1.json에 저장합니다. 저장 백업과 손상 파일 보존/복구를 제공합니다.
출정 중 방 진행은 저장하지 않으며, 게임을 종료하면 미보관 전리품을 잃습니다. 훈련 완료, 마을 물품, 장비·문신, 은화·진행 기록은 유지합니다.

## 절차적 생성

### 관문: 지레 또는 강공격

세 지역의 입구 방에는 닫힌 관문이 있습니다. 주변 적을 제압한 뒤 왼쪽 지레를 E로 당기면 조용히 열립니다. 오른쪽 관문을 강공격 두 번으로 부수면 지원군 2명이 나타납니다. 일반 공격으로는 부서지지 않으며, 지원군은 일반 전리품을 드롭하지만 방 완료 보상은 중복 지급하지 않습니다. 닫힌 관문은 통과와 다음 방 이동을 막고, 방을 정리한 뒤 안전 귀환은 허용합니다.

MDA: 지레 이동 또는 소음 발생 파괴 → 이동 시간과 추가 전투 위험 비교 → 바바리안의 힘으로 환경을 돌파하는 선택. DungeonGate는 관문 상태·표현, CampaignDirector는 방 진행·지원군·보상, Fighters는 실제 강공격 판정을 연결합니다.

0.4.1 협업: Claude Code가 DungeonGate와 Director 연결을 작성했고 Codex가 공격 연결·안내 UI·관문 표현·통합 검사를 완성했습니다. Windows 캠페인 113개(관문 신규 12개), 기존 전투 21개, 빌드 전 전투 규칙 12개 통과. 관문 두 해법·중복 소환 방지·보상 중복 방지·세 지역 이동을 포함합니다. 원본의 상자/시체 운반·투척 및 복합 환경 퍼즐은 추가 작업입니다.

DungeonGeneration.cs의 SeededDungeonGenerator가 독립적인 System.Random 시드로 세 지역의 적 종류·배치, 함정과 상자 위치를 생성합니다.
각 지역은 입구 → 보급로 또는 정예 사냥길 → 수호자 관문의 제약된 그래프입니다. 한 여정은 지역당 3방, 총 9방을 통과합니다.
보급로는 적 1/함정 없음, 사냥길은 정예 포함 적 3/추가 재료. 문을 통과할 때 부상·체력·전리품을 유지합니다.
지형 전체를 무작위 조립하는 시스템은 아닙니다. 읽기 쉬운 전투 무대를 유지하면서 전투와 보상 배치를 시드로 재현하는 방식입니다.

## 초기 6종 문신과 확장 기준

천둥(강공격 번개), 피의 룬(처치 회복), 질주(대시 충돌), 반격(패링 충격파), 메아리(강공격 0.25초 뒤 2차 타격), 서리 발걸음(회피 성공 시 주변 경직)의 6종을 구성합니다. 오른팔 면적은 2, 다리는 1입니다. 메아리는 팔 면적 2, 나머지는 각 부위 1을 사용합니다. 장착한 문신만 발동하며 구매 시 자리가 있으면 자동 장착합니다. 비워둔 슬롯은 저장 후에도 비어 있습니다. HUD는 장착 문신의 발동 조건·활성·침묵을 보여줍니다.

부상은 선택창 없이 자동으로 분노 적응을 적용합니다. 자동 보상은 기존 분노 수치를 초기값으로 사용하며, 문신의 활용보다 일부러 피격하는 것이 유리해지지 않도록 플레이 밸런스를 검토합니다.

SOLID 적용:
- S: BodyRules는 부상 규칙, EconomyService는 거래, IProfileStore 구현은 저장, SeededDungeonGenerator는 생성, CampaignHUD는 화면과 사용자 입력을 담당합니다.

- D: EconomyService는 구체적인 JSON 파일 클래스 대신 IProfileStore를 주입받습니다. 전 프로젝트가 완전히 의존성 주입화된 것은 아니며 Game/CampaignSession은 작은 프로토타입의 씬·회차 조정자입니다.

게임 패턴:
- 상태 머신: Game의 Phase, 적의 접근→예고→타격→회복 상태. 튜토리얼 단계도 실제 성공 이벤트로 전이합니다.
- Strategy: IDungeonGenerator / ILootRule로 생성과 전리품 규칙의 계약을 분리했습니다.
- Repository/저장 추상화: IProfileStore, JSON과 메모리 저장 구현.

- 타격감·난이도는 사용자 플레이를 통해 계속 조정해야 합니다.

Claude Code CLI가 EconomyDomain.cs와 씬/전투 연결 코드를 작성했고, Codex가 UI·던전·훈련·아트·테스트를 구현하고 통합했습니다.
0.3에서는 Claude Code가 입력 대시·자동 부상·훈련·검사 코드를 수정했고 Codex가 선택 UI 제거·문신 상태와 발동 표시·상태판 가독성을 통합하고 실행 검증했습니다.
Claude 데스크톱 앱 대화창에서 실행한 작업이 아니므로 앱 채팅 기록에는 표시되지 않습니다. 작업 보고서는 outputs/의 Claude 작업보고 파일에 있습니다.

## 0.4.2 박치기와 검증

MDA: 생명 비용·짧은 준비·행동 중단 → 적의 공격을 끊고 강공격 기회 확보 → 몸으로 싸우는 바바리안의 공격적 방어. 박치기는 도끼 타격 경로와 분리하여 천둥·메아리나 상자/관문 강공격 판정을 발생시키지 않습니다. 적 처치 시 피의 룬은 기존 처치 규칙을 따릅니다. 박치기 자체 비용은 HP에만 적용합니다. 0.5 이후 머리 외상은 적의 머리 대상 공격으로 누적됩니다.

Claude Code가 Fighters의 박치기 행동과 입력·기존 행동 상호 배제를 구현했습니다. Codex가 시선과 독립된 타격 방향 고정, 비전투 전환 취소, HUD·훈련 안내·시각 자세·실행 검사를 통합했습니다. 전투 판정은 Fighters, 표현은 PaintedCombatVisual/CampaignHUD로 분리했습니다.

최종 Windows 캠페인 129개, 기존 전투 회귀 21개, 빌드 전 전투 규칙 12개 통과. 새 행동의 비용·헛치기·중복 방지·단일 대상·보스/정예 중단·피격 취소·일시정지·방 정리·시선 반전·비전투 전환을 검사했습니다. 게임 화면의 Q 안내와 동작 중 표시도 확인했습니다. 테스트는 메서드 호출과 실제 프레임 업데이트를 사용하며 물리 키 입력 전체 검증은 아닙니다.

## 0.4 설계 적용과 협업

MDA: 부위별 면적과 6종 발동 조건(TattooCatalog/Fighters) → 반격+회복 또는 지연 강공격 등 행동 조합 선택 → 내 몸의 빌드를 만든다는 감각. 심각한 부상·사망의 부위 기록(CampaignSession.Settle) → 같은 실패가 특정 문신을 해금 → 다음 출정에 다른 대응을 시도하는 성장입니다.
책임 분리: TattooCatalog는 정의·해금·면적, EconomyService는 소유·장착·저장, BodyBuild.Has는 실제 활성 상태, Fighters는 전투 발동, CampaignHUD는 선택과 표시를 맡습니다. 기존 저장은 tattooLoadoutVersion으로 한 번만 이행합니다. 전투 효과 자체는 아직 Fighters에 모여 있어 완전한 효과 플러그인 구조는 아닙니다.
Claude Code가 도메인·저장 이행·검사를 작성했고 Codex가 전투·흉터 정산·문신소·회귀 검사를 통합했습니다. 실제 문신소 화면을 확인했고 Windows 빌드에서 101개 통합 검사와 21개 기존 전투 검사를 통과했습니다.
